# Upstream Candidates

> **Learnings from this project that may improve the blueprint for ALL projects.**
> During work, log anything that feels universal here. During retrospectives, review and decide whether to upstream.
> This file exists in every fork. The blueprint repo has its own copy for tracking contributions.

---

## How to Use This File

1. **During a project**: When you discover something that would improve the blueprint itself (not just this project), log it below.
2. **At retrospective**: Review all candidates. Classify as UPSTREAM (apply to blueprint) or PROJECT-ONLY (keep in fork).
3. **To upstream**: Create a PR against the blueprint repo with the change + rationale.

---

## Classification Guide

| Type | Example | Action |
|------|---------|--------|
| **Skill fix** | "The research skill should require competitor pricing, not just features" | Edit the skill in the blueprint |
| **Rubric fix** | "Security rubric weight for supply chain should be 2.0, not 1.5" | Edit the rubric in the blueprint |
| **Agent fix** | "QA runner should quarantine flaky tests before re-running" | Edit the agent in the blueprint |
| **Process fix** | "L2 tasks touching auth should get a security check" | Edit routing logic in CLAUDE.md |
| **New capability** | "Need a `/retrospective` skill" | Add to the blueprint |
| **Project-specific** | "Our API uses GraphQL, not REST" | Keep in fork's CONVENTIONS.md |
